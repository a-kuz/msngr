# QR codes for the link code and the safety number — live run, 2026-09-02

Main at b7d6157 plus the QR change committed right after this run. Three
simulators: `gate-runner` as bravo, `fable-charlie` as charlie, a fresh
`fable-link` (7820F10B) with no account. The simulator has no camera, so the
"scan" side is a picture: the other simulator's screen goes into the photo
library with `simctl addmedia`, and the app reads the QR from the picture it is
handed by the photo picker.

## What was in the way

Vision's `VNDetectBarcodesRequest` decodes the same screenshot on the host and
answers nothing on the simulator — the first attempt from the photo ended with
«На этом снимке нет кода входа». Core Image's `CIDetector` reads it on both, so
`QRCode.read` asks Vision first and falls back to Core Image.

## Linking a device by QR

1. `fable-link`: registration → «Войти по коду» — the code `N5FG-JDBS` with a
   QR under it (`msngr://link/N5FGJDBS`), the two-minute countdown running.
2. A screenshot of that screen added to bravo's library.
3. bravo: Settings → Устройства → Добавить устройство → «Считать код с фото» →
   the picture. The code is read, the lookup runs on its own, the screen shows
   «fable-link» with «Подтвердить».
4. «Подтвердить» on bravo; `fable-link` moves to «Войти как @bravo6? / Bravo
   Service». Cancelled there on purpose: the account was not given a third
   device, the flow past this point is the one verified on 2026-08-16.

## Comparing safety numbers by QR

1. charlie: Bravo Service → profile → «Код безопасности» — the sixty digits
   and their QR (`msngr://safety/<digits>`).
2. A screenshot of that screen added to bravo's library.
3. bravo: Charlie Service → profile → «Код безопасности» → «Сравнить по
   фото» → the picture. «Номера совпадают» in green, the «Проверено» toggle
   turns on by itself.

## Not run here

The camera as the reader (`DataScannerViewController`) — there is none on the
simulator; the picture path shares the decoder with it.
