# Disappearing messages leave the device

Run on 2026-08-27 on the `solo-live` simulator (`iPhone 17`, iOS 26.5) with a
private `alfa` home against a stand of its own on :8803; bravo is the headless
`msngrfixture send`.

## How

The picker offers 24 hours and up, which no run can wait out, so the chat's
timer was set to 20 s straight in the device's database with the app closed
(`UPDATE chat SET ttlSeconds = 20` for the direct chat with Bravo). The
setting path itself is covered by the info screen runs; this run is about the
sweep.

## Seen

```
14:52:08  alfa sends a text into the chat
14:52:09  bravo's fixture sends «ttl-probe from bravo»
14:52:12  the feed shows both
14:52:43  neither is in the feed; SELECT count(*) … WHERE expiresAt IS NOT NULL → 0
```

The outgoing message's deadline runs from the ack (`applySentAck` stamps
`expiresAt`), the incoming one's from its arrival (`applyIncoming`, the chat's
`ttlSeconds`); the sweep runs on the half-minute maintenance loop and on an
alarm armed for the nearest deadline (`scheduleNextExpiry`), which is what
took them out within the 30 s window rather than at the loop's next tick.
