# The session archive and glare resolution — live run

2026-08-29, headless over the real engine: `msngrfixture` (the same
`MsngrCore` — `SyncEngine`, outbox, `E2EE`, `IncomingDecryptor` — the app
runs) against a throwaway stand (`wrangler dev --port 8807`, its own persist
dir with the migrations applied), a fresh trio seeded into
`.claude/scratch/fable-glare/fixtures`.

## Staging the glare

A glare needs both sides to initiate X3DH before either has seen the other's
handshake. The seeded pair alfa–bravo had a live pairwise session from the
seed history, so both sides' `ratchetSession` rows for the peer were deleted
from their device databases; the server state (prekeys, chat, history) was
left as it was. Then two sends were fired in parallel:

```
msngrfixture send --as alfa --to bravo --text "glare from alfa" &
msngrfixture send --as bravo --to alfa --text "glare from bravo" &
```

Both engines came up sessionless, fetched the peer's bundle and sent a `pk`
first message — simultaneous initiation.

## What was seen

- Both first messages decrypted on both sides: each database holds the
  peer's text as an incoming row and its own as delivered.
- `pendingDecrypt` is 0 on both sides throughout — zero unreadable messages.
- The archive did its job on both devices: each side, holding its own
  initiator session, received the peer's `pk`, built the responder session
  and moved the current one into the archive (`IncomingDecryptor`, the
  `box.type == "pk"` path). After the run each side has one live session for
  the peer and a non-empty `archived` blob (449 and 511 bytes) that was NULL
  before the exchange.
- The resolved session carries traffic: a follow-up in each direction and a
  final round-trip all landed readable — five messages total on each side,
  every one with a status and a text, `pendingDecrypt` still 0.
