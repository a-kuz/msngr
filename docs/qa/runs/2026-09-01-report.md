# Reporting a message — live run

2026-09-01, simulators fable-a (carduser) and fable-b (peeruser), the shared
stand `msngr.a-kuz.online`.

## Scenario

1. peeruser wrote «buy now» to carduser; carduser accepted the request.
2. Long-press on the incoming bubble → «Пожаловаться» in the context menu
   (`2026-09-01-report-menu.png`).
3. The report sheet: the reason list with «Спам» preselected, an optional
   details field, the «Приложить сообщение» toggle on by default with the
   footnote that only what is attached leaves the device, and two actions —
   report, or report and block (`2026-09-01-report-sheet.png`).
4. «Пожаловаться и заблокировать»: the sheet closed, the chat shows «Вы
   заблокировали этого пользователя» with an unblock action
   (`2026-09-01-report-blocked.png`).

## Verified

- Server log: `POST /api/report 200`, then `POST /api/block 200`.
- D1 on the stand: the `reports` row carries reporter `carduser`, target
  `peeruser`, reason `spam` and the attached excerpt
  `[{"seq":1,"senderId":…,"text":"buy now"}]`; the `blocks` row for the pair
  exists.
- API validation is covered by the smoke report block: accepted with an
  excerpt, `bad_reason` and `no_target` rejected (`node test/smoke.mjs`,
  ALL PASS).
- The chat card of a direct chat and of a group offers «Пожаловаться» too
  (ChatInfoView), with blocking offered only when the target is a person.

A failed first attempt surfaced honestly as «Не отправлено» on the sheet: the
stand did not yet carry the `/api/report` route. After `rsync` + migration
0016 + restart on the stand the same button delivered.
