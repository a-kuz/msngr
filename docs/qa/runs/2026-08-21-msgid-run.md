# A message is (chatId, seq): the msgId ULID goes away

The server stops minting `msgId`; every reference that carried one — the pin,
the reply preview, the reaction and edit targets, delete-for-all — now carries
a seq. The client's rows drop the `msgId` column; `pendingApply` keys on
`targetSeq`, `pendingDecrypt` and `historyGap` key on `(chatId, seq)`.

`tsc --noEmit` clean.

## Found and fixed along the way (not part of this task, but broken in the tree before this run)

The worktree carried uncommitted changes from before this session that had
nothing to do with the msgId rework and regressed already-correct behavior:
`ChatViewModel.membersText`, `UnreadMarkerCell.title` and `lastSeenText` had
been rewritten from catalog-driven localization (`String(localized:)`, letting
the ICU plural rules and the device locale decide the text) to hardcoded
English/Russian literals, which is exactly the failure `LastSeenTests` and
`UnreadMarkerStateTests` caught (device locale is ru_RU on the gate-runner
simulator, so the hardcoded-English production code and the test's own
hardcoded-Russian expectation disagreed with each other, both wrong). Restored
to the catalog-driven form; the two test files were restored to their
catalog-comparison form as well. A number of unrelated files carried the same
kind of drift (test literals swapped to Russian, a whole test file deleted, a
fixture command removed, `scripts/progress.py` losing its root-anchor) — all
of it unconnected to msgId and reverted to match `main`.
