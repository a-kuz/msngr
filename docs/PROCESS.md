# Процесс разработки msngr

Цель — качество уровня Telegram/Signal. Прода нет, спешки нет: ни одно изменение не сдаётся без прохождения конвейера.

## Роли

Главный контекст — оркестратор: формирует пакеты задач, запускает worktree-агентов параллельно, мержит их ветки, разрешает конфликты, гонит гейт, ведёт бэклог и репорты. Исполнение (код, фиксы, прогоны) — у агентов. Каждому агенту в промпт: границы файлов, обязательная сборка+тесты, отчёт «сделано/проверено/не сделано». Живой стенд (wrangler dev :8787, два симулятора) общий — агенты его не перезапускают и не сносят стейт.

Симулятор — эксклюзивный ресурс: один симулятор в один момент времени принадлежит одному агенту (или владельцу). Параллельные UI-агенты обязаны создавать собственные симуляторы (`xcrun simctl create <имя> "iPhone 17"` → boot → install → регистрация свежего юзера) и удалять их после себя (`shutdown` + `delete`). Юзерская пара (dev 44CE2242, Pro Max 0E0CF155) выдаётся агенту только эксклюзивной бронью, когда владелец на ней не тестирует. Slow Animations в Simulator.app — глобальный тумблер: включил — выключи в конце.

## Конвейер качества

### Гейт `make check` (перед каждым коммитом)
1. `xcodegen` + сборка iOS-приложения.
2. Юнит-тесты ядра (`swift test` в MsngrKit) — крипто, синк, outbox.
3. Юнит-тесты раскладки (MsngrTests) — BubbleLayout.
4. UI-смоук (MsngrUITests) — запуск, регистрация, отправка текста, черновик, лонг-тап меню, attach-меню.
5. Серверный смоук (`node server/test/smoke.mjs`) — 34 проверки API/DO.
6. Сбор креш-логов симуляторов (DiagnosticReports) — свежие краши проваливают гейт.

### Правило одного изменения
- Микро-скоуп: одно поведение за раз.
- После изменения — живой прогон затронутого сценария на симуляторе (глазами, не только сборка).
- Затем полный `make check`.
- Регрессия, найденная после сдачи, получает воспроизводящий тест до фикса.

### Матрица состояний
Каждая фича прогоняется по строке матрицы, а не по happy path:

| Ось | Значения |
|-----|----------|
| Сеть | онлайн / офлайн / обрыв посреди операции / реконнект |
| Контент | короткий / длинный (200 строк) / эмодзи / RTL / ссылки |
| Устройства | один / два (отправитель+получатель) |
| Жизненный цикл | активно / фон→форграунд / kill во время операции |
| Состояние чата | новый (message request) / принятый / группа |

### Агентный цикл (пакетно, раз в итерацию)
1. Агент-аудитор читает код → список потенциальных багов → `docs/audits/`.
2. Агент-QA пишет тест-кейсы → `docs/qa/test-cases.md`.
3. Агент-прогонщик выполняет кейсы на двух симуляторах (координатная сетка поверх скриншота для точных тапов) → репорт в `docs/qa/runs/`.
4. Репорты разбираются: каждый подтверждённый баг получает воспроизводящий тест, затем фикс, затем строку в регрессионной суите.

### Диагностика крашей
- После каждого прогона (ручного и агентного): `scripts/collect-crashes.sh` собирает свежие `.ips` из `~/Library/Logs/DiagnosticReports` по процессу Msngr, складывает в `docs/qa/crashes/`, символизирует.
- Краш без разбора не закрывается.
