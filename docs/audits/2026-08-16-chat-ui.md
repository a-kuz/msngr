# Chat screen: owner review, 2026-08-16

Raised from screenshots of a live chat. Statuses: open / fixed / rejected.

## Being fixed now

1. **fixed** (415f32b, verified live 2026-08-16) — The feed does not fade out
   under the floating header. A bubble scrolling up meets the header and is cut
   off hard; it should dissolve into it — progressive blur plus the background
   tone, both gathering towards the top edge over roughly the header's height.
   Telegram and the Claude app were given as the reference. The header itself
   already floats; only the gradient under it is missing.

   Note: a first attempt misread this as being about the context menu and
   settled that backdrop instead (7db0954). That change stands on its own — the
   menu's blur used to leave the bubbles readable as smears — but it is not what
   was asked for.
2. **fixed** (eddc08f, verified live 2026-08-16) — The back button has to be the
   largest and most prominent control in the header. It is currently the system
   one, so it matches every other bar button instead of leading them.
3. **fixed** (0449090, verified live 2026-08-16) — Deleting a message asks "for everyone / for me" in a popover that
   covers the message it is about, so it is not clear what is being deleted.
   Instead: tapping Delete enters selection mode with that message already
   selected, more messages can be added, and the confirmation sits at the bottom
   as two actions — for everyone and for me.

## Planned

4. **fixed** — Search inside a chat. A magnifier in the header turns it into a
   field, the matches cover the feed, a chosen one is shown in place, and the bar
   under the feed carries the position in the result and the two steps through
   it; «Отмена» puts the reader back on the message they opened search from. Run:
   `docs/qa/runs/2026-08-16-chat-search-run.md`.
5. **fixed** (8530d78, f75df1b, 99aff7e) — Tapping the status bar must go to the beginning of the chat, not to
   its end. The list is inverted, so the system behaviour lands on the wrong side.
   The input field held the tap as a second scroll view and now declines it. The
   tap itself belongs to SpringBoard and XCUITest cannot deliver it on the
   simulator, so the wiring is checked in `MsngrTests/StatusBarTapTests`.
6. **fixed** (556bacd, verified live 2026-08-16) — Sending a message must move the feed to the end from wherever it is
   scrolled, and play the bubble's appearance animation there. Both the landing
   and the animation are recorded in `2026-08-16-chat-header-run.md`.
7. **fixed** (b390c03, 17a21be, verified live 2026-08-16) — A bubble carrying a reaction sits unevenly: the time and the ticks
   keep different insets from the ones a plain bubble uses.
8. **fixed** (2cbaf3c, verified live 2026-08-16) — In the context menu's selection state, dragging over the text
   should select it directly, without going through a "Select text" item first.
   The "Select text" row and the screen behind it are gone.

Run reports: `docs/qa/runs/2026-08-16-chat-ui-run.md` for items 3, 5, 6, 7 and 8,
`docs/qa/runs/2026-08-16-chat-header-run.md` for items 1 and 2 and their re-check.

## Rejected

  It works through the screen's own edge gesture; the system's interactive pop
  does not run while the header draws its own back button.
