# UI-спека: детали, которые обязаны быть точными

## Баббл сообщения: размещение времени (эталон — Telegram)

Блок статуса = время (HH:mm) + галочки (исходящие) [+ "изменено"]. Три случая:

1. **Влезает в последнюю строку** — статус стоит inline сразу после текста последней
   строки, прижат к правому краю баббла. Ширина баббла = max(строки текста,
   последняя строка + статус).
2. **Не влезает, но баббл шире** — статус переносится на отдельную строку,
   прижат вправо (текст занимает почти всю ширину баббла).
3. **Многострочный текст, у последней строки есть место** — статус сидит на одной
   строке с последним фрагментом текста (не на новой строке).

Реализация: TextKit-замер последней строки; если `lastLineWidth + statusWidth +
gap <= maxBubbleWidth` → случай 1/3, иначе статус на новой строке. Для медиа
без подписи — статус в капсуле-оверлее в правом нижнем углу изображения.

## Замороченное (обязательное, эталоны — Telegram-iOS / Signal)

- **Реакции**: анимация появления (spring scale + разлёт частиц у эмодзи),
  раскладка групп разных реакций под бабблом — капсулы «эмодзи + счётчик»,
  флоу-layout с переносом строк, своя реакция подсвечена; тап по капсуле
  снимает/ставит; лонг-тап — список кто поставил. Капсулы участвуют в расчёте
  ширины/высоты баббла.
- **Pushout-расчёт строк**: высота ячейки считается точным TextKit-замером со
  всеми переносами; блок статуса «выталкивается» (pushout) на новую строку,
  только если реально не влезает в последнюю строку — см. три случая выше.
  Реакции и reply-плашка добавляются к высоте детерминированно, замер кэшируется.
- **Стейты телефона и сокет**: переходы fg/bg (bg → grace-период, потом закрытие
  сокета с сохранением курсоров), wifi↔cellular (мгновенный reconnect по
  NWPathMonitor), lock screen, kill, network flap — очередь outbox переживает
  всё; после reconnect: sync по курсорам, повторная отправка недоставленного,
  без дублей (clientMsgId). Пинг/понг с таймаутом для обнаружения мёртвого сокета.
- **Пуши vs ин-апп**: если приложение в fg и сокет жив — системный пуш не
  показываем (NSE/willPresent гасит по chatId открытого чата); для остальных
  чатов в fg — своя ин-апп плашка сверху (tap → чат). Бейджи консистентны.
- **Видео**: исходящее — компрессия H.264/HEVC с прогрессивным mp4 (faststart),
  первый кадр как превью с blurhash, автоплей mute в баббле опционально,
  плеер с скраббингом; загрузка стримингом (range-запросы к R2).
- **Фото-превью**: blurhash/thumbhash едет внутри E2E-сообщения → плейсхолдер
  мгновенно, потом прогрузка полного; даунскейл до разумного (1280) + JPEG q80.
- **Голосовые**: waveform из реальных амплитуд (100 бакетов в сообщении),
  при проигрывании закрашивается по прогрессу с анимацией, тап по waveform — seek.
- **Сетка альбомов**: телеграм-мозаика для 2–10 фото (алгоритм пропорций
  Telegram: раскладка по аспектам в строки/колонки), альбом = один баббл,
  групповой статус-оверлей.

## Прочее обязательное

- Галочки: одна серая = отправлено на сервер, две серые = доставлено, две
  зелёные/синие = прочитано. Часики — в outbox (ещё не на сервере).
- Группировка бабблов: последовательные сообщения одного автора в течение минуты —
  без повторного аватара/имени, уменьшенный вертикальный зазор, хвостик только у последнего.
- Разделители дат ("Сегодня", "Вчера", "5 марта") — плавающие при скролле.
- Скролл-позиция чата сохраняется; кнопка "вниз" с бейджем непрочитанных.
- Свайп сообщения вправо = reply; двойной тап = реакция по умолчанию.
- Инвертированный список: открытие чата мгновенно с последних сообщений,
  пагинация вверх без прыжков контента.
- Typing-индикатор в чат-листе и в шапке чата ("печатает…", в группе — с именем).
- Голосовые: запись по удержанию, slide-to-cancel, свайп вверх = lock; waveform
  из реальных амплитуд; скорость ×1/×1.5/×2; прослушанность меняет цвет waveform.
- Черновики сохраняются per-chat, отображаются в чат-листе красным "Черновик:".
- В чат-листе: время последнего сообщения, бейдж непрочитанных, галочки своего
  последнего сообщения, pin-иконка, mute-иконка, превью ("Фото", "Голосовое сообщение", …).
